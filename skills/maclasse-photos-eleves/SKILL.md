# Photos élèves maclasse.photo → Charlemagne / EcoleDirecte

À utiliser dès que l'utilisateur parle de photos de classe, photos des élèves, maclasse.photo, trombinoscope, vignettes, ou veut charger les photos dans Charlemagne ou EcoleDirecte. Produit un dossier `IDELEVE.jpg` pour l'affectation automatique Charlemagne, plus un index et un rapport. La skill ne fait jamais l'affectation dans Charlemagne : elle livre le dossier, l'utilisateur lance les traitements natifs. Les photos arrivent ensuite dans EcoleDirecte par le transfert Charlemagne.

**Edumoov / Educartable : pas de photo élève.** Vérifié le 15/10/2026 dans le code des applications Edumoov (app.edumoov.com et Cartable) : la fiche élève n'a aucun champ photo (nom, prénom, date de naissance, sexe, niveau, classe, INE, parents, groupes) ; les élèves s'affichent avec une icône générique ; seuls les comptes adultes ont un avatar ; aucun import de photos ni trombinoscope, ni dans l'interface ni par l'API. Le pipeline ne produit plus de dossier pour Edumoov depuis le 15/10/2026 (un ancien `edumoov_par_classe/` dans une préparation antérieure est sans usage). Si l'utilisateur veut les photos dans Edumoov, expliquer que ce n'est pas possible aujourd'hui et proposer, s'il le souhaite, une question au support Edumoov (ticket existant n°51164) — en rappelant le droit à l'image des familles et la protection des médias Edumoov par UUID, pas encore corrigée (engagement avant fin 2026). Ne pas contourner (pas de photo d'élève postée dans le cahier de vie ou le cartable pour en tenir lieu).

## Outils

- **MCP `maclasse`** (dépôt `~/dev/maclasse-mcp`, identifiants dans `~/.maclasse-mcp/credentials.json` créé par l'utilisateur, fichiers sous `~/Charlemagne/photos/maclasse/<8 premiers caractères de l'uuid projet>/`) : lecture `maclasse_statut`, `maclasse_prises_de_vues`, `maclasse_classes`, `maclasse_eleves`, `maclasse_association_classe` ; exports `maclasse_telecharger_vignettes`, `maclasse_telecharger_trombinoscope`, **`maclasse_preparer_photos`** (pipeline complet) ; écriture `maclasse_importer_noms_prepare`, `maclasse_associer_noms_prepare`, `maclasse_retirer_noms_prepare` + `maclasse_write_confirm` / `maclasse_write_cancel` (jeton ; `MACLASSE_ENABLE_WRITES=1` requis, à 0 dans Claude Desktop par défaut). Toute écriture : montrer l'aperçu, attendre l'accord explicite, puis confirmer. Maintenance et validation : doc projet `maclasse-mcp-connecteur.md`.
- Repli sans MCP : navigateur intégré (l'utilisateur saisit lui-même le mot de passe ; exports via les boutons « Vignettes élèves » et « Trombinoscope », fichiers dans `~/Downloads`, accord demandé avant chaque téléchargement) puis `python -m maclasse_mcp.preparer --vignettes … --trombi-codes … --trombi-noms … --eleves … --classes classes_map.json --sortie .` (ou `~/Charlemagne/photos/maclasse/preparer_photos.py`, même logique).
- Liste élèves : outil MCP Charlemagne `liste_eleves` (tous actifs), réponse JSON enregistrée telle quelle (clé `eleves`).

## Ce qu'il faut savoir sur la plateforme

- Une prise de vue par an (ex. SM26 = 17/09/2026). Les images affichées sur le site sont **filigranées** : ne jamais les récupérer. Seul export propre : « Vignettes élèves » (ZIP, un dossier par classe, JPG 400×533 ~60 Ko sans filigrane, nommé `Nom Prenom.jpg` si un nom est associé, sinon par code d'accès). Le site et son CDN ne sont joignables que depuis le Mac (MCP) ou le navigateur intégré, pas depuis le conteneur.
- Trombinoscope PDF (par classe, 6 colonnes, ordre de création des fiches) : libellé « nom de l'élève » (nom associé, sinon code) ou « nom de la photo » (nom de fichier du photographe, en pratique `NOM Prénom.jpg`). **La paire des deux donne la correspondance photo ↔ élève** sans association manuelle ; les deux PDF doivent être générés avec les mêmes options de disposition.
- Les codes d'accès sont destinés aux familles : ne pas les recopier dans la conversation sans raison (`maclasse_eleves` ne les renvoie que si `avec_codes=True`).
- Photos de groupe : pas d'export sans filigrane côté école → les demander au photographe.
- Classes maclasse ↔ Charlemagne (2026) : CE1A→CE1 A, CE1B→CE1 B, CE2A/B→CE2 A/B, CM1A/B→CM1 A/B, CM2A/B→CM2 A/B, CPA→CP A, CPB→CP B, GS→GS, MS→MS, MS-GS→MGS, PS→TPSPS, PS-MS→PS/MS ; « Fratries » (photos de fratries) ignorée. Détails des pages et routes : doc projet `maclasse-photo-fonctionnement.md`.

## Déroulé

1. **Liste élèves Charlemagne** → `~/Charlemagne/photos/maclasse/<année>/liste_eleves.json`. Comparer les effectifs par classe avec `maclasse_classes` (nb de photos) et signaler les écarts (absents le jour de la prise de vue).
2. **Pipeline** : `maclasse_preparer_photos(uuid_projet, liste_eleves, classes_map)` télécharge le ZIP et les trombinoscopes `codes` et `nom_photo`, rapproche chaque photo de la liste Charlemagne (exact, sinon approximatif ≥ 0,80 et sans concurrent proche) et produit `charlemagne_ideleve/`, `index_photos_eleves.csv`, `mapping_codes_noms.json`, `RAPPORT.md`. Sans `classes_map`, correspondance automatique sur le nom normalisé avec les classes sans correspondance signalées. Rien n'écrase les sources.
3. **Relire le rapport avec l'utilisateur** : rapprochements approximatifs (orthographe du photographe ≠ Charlemagne — chacun doit être unique et plausible), photos non appariées (à arbitrer, jamais devinées), élèves sans photo, trombinoscopes incohérents (à regénérer avec les mêmes options).
4. **Association des noms sur la plateforme** (recommandé : les familles voient le nom sous la photo, les exports suivants sortent nommés). Par classe : `maclasse_importer_noms_prepare` (liste Nom/Prénom Charlemagne de la classe ; remplace la liste existante) puis `maclasse_associer_noms_prepare` avec `[{uuid_eleve, nom}]` construits depuis `index_photos_eleves.csv` (code → nom) et `maclasse_eleves(avec_codes=True)` (code → uuid élève) ; vérifier l'aperçu (nb associations = nb photos de la classe, aucune erreur) avant chaque confirmation, puis relire avec `maclasse_association_classe` (0 photo sans nom). Ne jamais utiliser le bouton « Attribution automatique » de la plateforme : l'ordre de prise de vue n'est pas l'ordre alphabétique. Fait pour SM26 le 15/10/2026 (398 noms, 15 classes).
5. **Rappeler les étapes natives** : Charlemagne › Administratif › Outils › Affectation des photos › Élèves (RAZ optionnelle, puis affectation automatique sur `charlemagne_ideleve/`, nommage par identifiant), puis « À intégrer au prochain envoi » (Charlemagne Outils › EcoleDirecte) ou Transfert vers EcoleDirecte pour EcoleDirecte (skill `charlemagne-affectation-photos` pour le pas à pas). Conseiller une relecture du trombinoscope avec noms par les enseignant·e·s avant l'import : une photo mal affectée écrase la mauvaise fiche. Pas d'étape Edumoov (voir plus haut).

## Vigilance données

Photos nominatives d'élèves mineurs et codes d'accès familles : pas de photos, de noms ni de codes dans des exemples, tests ou fichiers versionnés ; dossiers livrés uniquement à l'utilisateur, rien de publié. Le mot de passe de la plateforme n'est jamais saisi par Claude ni recopié ailleurs que dans `~/.maclasse-mcp/credentials.json`, créé par l'utilisateur.
